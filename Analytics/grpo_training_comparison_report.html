Architectural Design Choices
🔑 Grouped Query Attention (GQA)

Qwen3-1.7B uses Grouped Query Attention with 16 query heads sharing 8 key-value heads (2:1 ratio). This reduces KV-cache memory by 50% compared to standard MHA while maintaining most of the model quality, enabling faster inference and longer context windows.

Query Heads16 KV Heads8 GQA Ratio2:1 Head Dim128 KV Cache Savings50% vs MHA
🌀 Rotary Position Embeddings (RoPE)

Uses RoPE with a very high base frequency of 10,000,000 (vs standard 10,000), allowing natural extrapolation to longer sequences. Combined with a 32K max position, this supports extended reasoning chains needed for math tasks.

Position EncodingRotary (RoPE) θ Base10,000,000 Max Positions32,768 Scaling TypeDefault (no NTK/YaRN)
⚡ SwiGLU FFN

The feed-forward network uses SwiGLU (SiLU gating), which splits the intermediate computation into gate and up projections. With an intermediate size of 6,144 and hidden size 2,048, the expansion ratio is 3:1. SwiGLU provides better gradient flow and training stability than standard ReLU FFNs.

ActivationSiLU (Swish) Gate + Up → Down2048 → 6144 → 2048 Expansion Ratio3.0× FFN % of Params61.5%
🧠 Thinking / Reasoning Mode

Qwen3 models support a dual-mode architecture with explicit thinking tokens. The tokenizer includes special <think> and </think> tokens that bracket chain-of-thought reasoning. This is why the reasoning_reward_fn returned +0.5 — the model enters thinking mode but was truncated at 256 tokens before producing a final answer.

Critical Findings
🚨
100% Completion Clipping — Root Cause of Training Failure
Every completion hit the max_new_tokens=256 cap. clipped_ratio=1.0 and mean_terminated_length=0 confirm nothing ever produced an EOS token. GSM8K chain-of-thought solutions need 400–800 tokens. The model starts reasoning but can never finish.
🚨
Zero Gradient Flow — GRPO Advantage Collapse
Loss = 0 and grad_norm = 0 for every step. GRPO computes advantages from relative reward within each group. When all completions get identical rewards (reward_std = 0), advantages are zero → no gradient signal. frac_reward_zero_std ≈ 1.0.
🚨
Correctness Reward Flatlined at -1.0
The model never solved a single GSM8K problem — it can't produce a correct answer if it can't finish generating one. Rare -0.981 outliers on Pytche suggest a tiny fraction of completions may have partially matched.
⚠️
Format Reward Stuck at -0.5
Expected output format (e.g. \boxed{answer}) never appears because completions are truncated before the answer formatting step.
ℹ️
Reasoning Reward is the Only Positive Signal
+0.5 consistently — the model does enter thinking mode with <think> tokens. This is encouraging: the model knows HOW to reason, it just needs more tokens to finish.
⚠️
Clip Ratio Zero — Policy Never Diverged
PPO clipping was never triggered because the policy ratio π/π_ref stayed at 1.0 (no updates occurred).

Action Items for Next Training Run
1
Increase max_new_tokens to 512–1024
Priority: CRITICAL. This is the root cause. GSM8K chain-of-thought solutions typically require 400–800 tokens (especially with <think> blocks). At 256 tokens, 100% of completions are truncated. Set max_new_tokens=768 as a starting point. This will increase step time proportionally (~3× longer generation) but is essential for any learning.
2
Increase GRPO group size (num_generations)
Priority: HIGH. GRPO needs reward variance within each group to compute meaningful advantages. With all completions equally bad, advantages are zero → no gradients. Increase the number of completions per prompt (e.g., from 4 to 8 or 16) to increase the chance of at least one completion being correct.
3
SFT warm-start before GRPO
Priority: HIGH. The base Qwen3-1.7B doesn't produce correctly formatted GSM8K solutions out of the box. A short supervised fine-tuning phase on 100–500 examples with correct chain-of-thought format would move the model into a regime where some completions earn positive reward, enabling GRPO to learn.
4
Enable mixed precision (bf16)
Priority: MEDIUM. Both runs used full precision. Enabling --mixed_precision=bf16 in the accelerate config would reduce memory usage and improve throughput — especially for the generation phase which dominates step time (80%+). Qwen3 was trained in bf16 natively.
5
Disable find_unused_parameters
Priority: LOW. DDP warns no unused parameters were found. Setting find_unused_parameters=False skips an extra autograd graph traversal each step — a small but free performance gain.
6
Use Hecate cluster for future runs
Priority: LOW. Hecate delivered 1.83× faster training with 2.66× faster generation. For longer runs with proper hyperparameters (more tokens, more epochs), this translates to significant wall-clock savings.
