Critical Findings
🚨
100% Completion Clipping — Root Cause of Training Failure
Every single completion across all steps hit the max_new_tokens=256 cap. clipped_ratio=1.0 and mean_terminated_length=0 confirm no completion ever produced an EOS token or answer delimiter. GSM8K problems require chain-of-thought reasoning that typically needs 400–800 tokens. At 256 tokens the model can start reasoning but never finish or produce a boxed answer.
🚨
Zero Gradient Flow — GRPO Advantage Collapse
Loss = 0 and grad_norm = 0 for every step on both clusters. GRPO computes advantages from the relative reward within each group. When all completions receive identical rewards (reward_std = 0), the advantage for every token is zero, producing no gradient signal. This is evidenced by frac_reward_zero_std ≈ 1.0 (98.75–100% of groups had zero reward variance).
🚨
Correctness Reward Flatlined at -1.0
The correctness reward function consistently returned -1.0 (with rare -0.981 outliers on Pytche). The model never solved a single GSM8K problem because it couldn't finish generating a complete answer within the token budget.
⚠️
Format Reward Consistently Negative
Format reward stuck at -0.5, indicating the model never produced the expected output format (e.g., \boxed{answer}). This is a direct consequence of truncation — the model generates reasoning tokens but runs out of budget before reaching the answer formatting step.
ℹ️
Reasoning Reward is the Only Positive Signal
The reasoning reward function returned +0.5 consistently, confirming the model does enter a thinking/reasoning mode. This is a positive sign — the model knows to reason, it just can't complete the reasoning within the token limit.
⚠️
Clip Ratio is Zero — Policy Never Diverged
Both clip_ratio/high and clip_ratio/low remained 0 throughout training. Since no gradient updates occurred, the policy ratio π/π_ref stayed at 1.0, and the PPO clipping mechanism was never triggered.

Action Items for Next Training Run
1
Increase max_new_tokens to 512–1024
Priority: CRITICAL. This is the root cause. GSM8K chain-of-thought solutions typically require 400–800 tokens. At 256 tokens, 100% of completions are truncated before producing an answer. Set max_new_tokens=768 as a starting point. This will increase step time proportionally but is essential for any learning to occur.
2
Increase GRPO group size (num_generations)
Priority: HIGH. GRPO needs reward variance within each group to compute meaningful advantages. With uniform rewards (all completions equally bad), advantages are zero → no gradients. Increase the number of completions per prompt (e.g., from 4 to 8 or 16) to increase the chance of at least one completion being correct, creating the contrast GRPO needs.
3
SFT warm-start before GRPO
Priority: HIGH. The base Qwen3-1.7B model doesn't produce correctly formatted GSM8K solutions out of the box. A short supervised fine-tuning (SFT) phase on 100–500 examples with correct chain-of-thought format would move the model into a regime where some completions earn positive reward, enabling GRPO to learn.
4
Enable mixed precision (bf16 or fp16)
Priority: MEDIUM. Both runs used full precision. Enabling --mixed_precision=bf16 in the accelerate config would reduce memory usage and potentially improve throughput, especially for the generation phase which dominates step time (80%+).
5
Disable find_unused_parameters
Priority: LOW. The DDP warning shows no unused parameters were found. Setting find_unused_parameters=False would skip an extra autograd graph traversal each step, providing a small but free performance gain.
6
Use Hecate cluster for future runs
Priority: LOW. Hecate delivered 1.83× faster training with 2.66× faster generation. For longer runs with proper hyperparameters, this translates to significant wall-clock savings. Prefer Hecate unless it's capacity-constrained.
