Key insights
Validation reliability dominates.
Three of four machine-readable historical Qwen rows have non-finite eval loss. The current fixed script is a better baseline because it uses safer evaluation and deterministic seeds.
Cluster timings are directional only.
The same 500-example GRPO recipe is described at ~15 min on Pytche/B200, ~6 min on Hecate/Rubin, and ~40 min in a generic cluster note. These are not controlled hardware benchmarks.
Provenance is improving.
The newer Qwen3.5 and Qwen3-VL pipelines write run summaries/eval outputs and capture GPU/system information when executed. Extend that pattern to every experiment.
Image mapping catches attribution errors.
The nemo3nano-ft-* images follow the 8×H100 recipe; the document explicitly says Pytche/Blackwell is next. The GRPO recipe is also text/math, despite a “multimodal” conclusion.

Synthesis

Insights & recommended next experiments

Cross-run insights
Finite evaluation first.
A lower training loss is not enough to select a winner when 3/4 historical eval losses are NaN.
Recipe drift must be versioned.
The current Qwen suite changes rank/dropout/weight decay relative to historical measured rows; compare results only with exact manifests.
GRPO reward design is part of the model.
The correctness, boxed-format and reasoning-line rewards should be versioned alongside model/data/hardware because they materially define the optimization target.
Multimodal runs need task-level evaluation.
Cosmos and Qwen-VL training completion does not establish generated-video or vision-language quality.
Screenshot evidence is useful but secondary.
Use screenshots to validate execution and telemetry, then export raw W&B histories and run manifests for quantitative comparison.
Hardware conclusions need controlled repeats.
Container image, commit, seed, dataset fingerprint, batch semantics and I/O must match before treating runtime differences as architecture speedups.
Recommended next experiments
  1. Rerun the exact four historical Qwen configs through the current finite-eval path with immutable run manifests.
  2. Run a one-factor r8/r16/r32 rank sweep with LR/dropout/weight decay fixed.
  3. Benchmark B200 vs Rubin GRPO with the same commit, container digest, seed, dataset fingerprint and reward functions; collect tokens/s, peak VRAM and held-out exact match.
  4. Compare Base → SFT/QLoRA → SFT+GRPO on the same held-out math set.
  5. Export W&B history into the repository (CSV/JSON), not only screenshots.
