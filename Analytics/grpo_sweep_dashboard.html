💡 Key Insights

Learning Rate is the Most Impactful Hyperparameter

Critical Finding
1e-5
Optimal LR
+4%
vs Baseline (5e-6)
−6%
Over-shoot (2e-5)

Across all 5 runs, learning rate had the strongest correlation with final accuracy. The optimal range for 1-epoch QLoRA GRPO is 5e-6 to 1e-5.

Evidence

  • LR 5e-6 (run1) → 72% — too conservative, under-explores in 1 epoch
  • LR 1e-5 (run3) → 76% — sweet spot, aggressive-but-stable
  • LR 2e-5 (run2) → 74% — overshoots, higher loss (0.0087 vs 0.0052)
  • LR 2e-6 (run4) → 74% — way too conservative even with large LoRA
Takeaway: For 1-epoch QLoRA GRPO with cosine schedule, start at 1e-5. Scale down only if unstable or multi-epoch.

Run5 (16 gen, 500 samples) performed worse than run1 (4 gen, 1000 samples). Only 31 unique prompt batches — too little diversity.

  • Run1: 4 gen × 1000 = 250 unique batches → 72%
  • Run2: 8 gen × 1000 = 125 unique batches → 74%
  • Run5: 16 gen × 500 = 31 unique batches → 70% ❌

Qwen3's thinking mode consumed entire 512-token budget on <think> blocks, never producing \boxed{}.

The Fix (3 layers)

  • /no_think prefix in system prompt
  • extract_text() strips residual <think> blocks
  • enable_thinking=False in eval template
Takeaway: Always verify generation mode compatibility with your reward function and token budget.

Reward Function Design Matters

Design
4

Multi-component reward (correctness + format + reasoning + length)provided richer signal than binary correct/incorrect.

What Worked

  • Correctness (+3.0): Model prioritizes right answer
  • Format (+1.5): Teaches \boxed{} independently
  • Partial credit (+1.0): Prevents catastrophic forgetting
  • Reasoning bonus: Encourages step-by-step even when wrong

What Could Improve

  • Format reward saturated early (~1.4-1.5) — reduce weight
  • No reward for intermediate steps being mathematically valid
  • Consider Process Reward Model (PRM) for step-level feedback
Takeaway: Start with dominant correctness signal, add auxiliary rewards. Watch for reward saturation.

Qwen3-1.7B Architecture

  • Type: Transformer decoder-only (causal LM)
  • Layers: 28 transformer blocks
  • Hidden dim: 2048
  • Attention heads: 16 (GQA with 4 KV heads, 4:1 ratio)
  • Context window: 32,768 tokens
  • Vocabulary: 151,936 tokens
  • Positional encoding: RoPE
  • Activation: SwiGLU (gate + up + down projections)
  • Special: Dual-mode thinking (disable with /no_think)

QLoRA (4-bit NF4)

  • Quant type: NormalFloat 4-bit — optimal for normally-distributed weights
  • Compute dtype: bfloat16 (preserves dynamic range)
  • Double quant: Enabled (saves ~0.4 bits/param)
  • Memory: ~4× reduction (6.8 GB fp16 → ~1.7 GB 4-bit)

LoRA Configuration

  • Targets: q, k, v, o, gate, up, down (all linear layers)
  • Best rank: 32 (alpha=64, scaling=2.0)
  • Dropout: 0.05
  • Trainable at r=16: ~23.8M (1.4%)
  • Trainable at r=32: ~47.6M (2.8%)
  • Trainable at r=64: ~95.2M (5.5%)
Rationale: Qwen3-1.7B chosen for fast iteration. 7-target LoRA maximizes adaptability. At r=32, only 2.8% of params train — making GRPO feasible with limited compute.

GRPO Algorithm

  • Full name: Group Relative Policy Optimization (DeepSeek, 2024)
  • Key idea: Generate N completions/prompt, compute relative advantage within group
  • Advantage: (reward − mean) / std within group
  • vs PPO: No value head, no GAE — simpler, cheaper
  • vs DPO: Online generation (not just preference pairs)

Optimizer & Schedule

  • Optimizer: AdamW
  • LR schedule: Cosine decay → 0 over 1 epoch
  • Gradient clipping: max_grad_norm=1.0
  • Effective batch: per_device × grad_accum × gpus = 64 samples/update

Training Dynamics (run3, best)

  • Step time: ~19s/step (stable)
  • Generation: ~12s/step (60% of step = inference)
  • Reward: 4.51 → 4.85 → 4.97 (monotonically ↑)
  • Entropy: 0.15 → 0.13 (slight decrease, not collapsing)
  • Grad norm: 0.08-0.17 (stable)
  • Tokens: 1.55M total generation tokens

Memory & Resume

  • Gradient checkpointing: Enabled (trades compute for memory)
  • Peak VRAM: ~6 GB/GPU
  • Checkpoints: Every 100 steps (save_total_limit=2)
  • Sweep resume: sweep_analytics.json tracks completed runs
  • Clean reload: Fresh model per run (clean starting point)
Training Insight: GRPO spends ~60% time on generation (inference), ~40% backward pass. Optimizing generation (speculative decoding, TensorRT) = highest ROI.

Reward Function Architecture

Design Choices
4
Components
6.0
Max Score
~5.0
Avg Best Run
50%
Correctness Wt

1. Correctness (dominant)

  • +3.0: Exact \boxed{} match
  • +1.0: Within 1% relative error
  • −0.5: Wrong \boxed{} value
  • −1.0: No \boxed{} at all

2. Format (shape signal)

  • +1.5: Proper \boxed{content}
  • +0.2: Partial ("boxed" or "answer" appears)
  • −0.5: No formatting attempt
  • Saturated to ~1.4-1.5 within first few steps

3. Reasoning (quality)

  • +0.5: ≥5 lines of reasoning
  • +0.3: ≥3 lines
  • +0.1/indicator: Math symbols & reasoning words (capped +0.5)
  • −0.5: <20 chars (degenerate)

4. Length Penalty (regularization)

  • −0.5: <50 chars (too short)
  • −0.3: >2000 chars (too long)
  • 0.0: 50-2000 chars (normal range)
  • Rarely triggered — outputs averaged 270-330 tokens
Design Principle: Dominant correctness signal (+3.0), quick-saturation format/shape rewards, light regularization. Avoid zero-std groups (kills GRPO advantage signal).
